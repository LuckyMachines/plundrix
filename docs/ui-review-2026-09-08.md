# UI Review - 2026-09-08

Scope: 12 canonical player-facing states at desktop and mobile widths.

## Highest-leverage gaps found

1. The live action dock used three viewport-driven columns inside a constrained sidebar. Search and Sabotage labels and content clipped even though the page itself had no horizontal overflow.
2. The live opponent rail also responded to viewport width rather than its available container. Two player summaries were squeezed into a four-column grid and their lock, tool, and readiness statistics collided.
3. Visual review had captures but no bounded approval contract: there was no canonical manifest, approved-reference comparison, reasoned baseline history, or one-command contact sheet covering the full player journey.

## Changes made

- Made the live action group and opponent rail container-responsive.
- Gave opponent statistics an explicit non-wrapping grid and reduced excessive action-label tracking.
- Added a 12-surface, 24-render visual contract with deterministic fixtures, approved baselines, comparisons, contact sheet, Axe checks, geometry checks, and approval history.
- Extracted canonical visual tokens into `app/src/styles/tokens.css` and added a governance assertion for the required token families.
- Linked the matrix to the existing one-active-experiment ledger and browser release gate.

## Evidence

- `npm run test:ui-system`: pass.
- `npm --prefix app run build`: pass.
- `npm run ui:review`: 24/24 pass with 0.000% diff after approval; no serious/critical Axe findings, horizontal overflow, visible unloaded images, or monitored clipped containers.
- Original-resolution contact sheet inspected at `app/reports/ui-review/latest/contact-sheet.png`.

This is T2 rendering and interaction-geometry evidence. It does not establish player comprehension, delight, or return intent; those remain open T3/T4 evidence tasks.

## Decision-first remediation pass

The complete review then found a second class of issues: important decisions and outcomes were visually correct but arrived too late, especially on mobile.

### Changes made

- Compressed Instant and Vault Run status, rival, and action surfaces so the current decision appears in the first mobile viewport.
- Promoted each Instant result into a causal outcome surface before the next round, and reduced the final briefing to a clear rematch/replay hierarchy.
- Added visible, in-context wallet actions and plain-language launch progress to live lobby and live play.
- Reordered Career around objectives and Replays around visual stories instead of zero-heavy metrics and filters.
- Added distinct route art, a mobile comparison rail, tighter Hub/setup/Workshop copy, and stronger responsive containment.
- Stabilized canonical captures by freezing live-chain time, controlling focus and scroll, and excluding generated reports from Vite file watching.

### Verified result

- `npm run ui:review`: 24/24 canonical renders pass.
- `npm run improve:release`: 11/11 checks pass with zero failed or flaky checks.
- Every intentional baseline change has a recorded approval reason.

The remaining work is human evidence: four newcomer sessions and two returning-player sessions after seven days.

## Layout and typography system pass

- Added semantic typography roles for hero, page, section, card, body, interface, and label text.
- Added bundled Barlow for readable prose while retaining Barlow Condensed for display and JetBrains Mono for controls and data.

- Added reusable page, stack, cluster, auto-grid, rail, and decision-layout primitives.
- Added a four-width stress surface covering 320px, 390px readable mode, 768px, and 1440px with long labels and dense values.
- Added automated font-loading, text-overflow, line-measure, type-floor, and source-contract checks.

Verified result: 24/24 canonical renders and 4/4 type/layout stress renders pass with zero serious or critical Axe findings. The complete release gate passes 11/11 with zero failed or flaky checks.
